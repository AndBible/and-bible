# PR #3794 — Track Multiple Chapter Reads — Cleanup Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Refactor Andrew Rogers' PR #3794 ("track multiple chapter reads") into a mergeable state by collapsing the dual data model into a single `ChapterReadHistory` table, squashing the migration chain `7→8→9→10` into one clean `7→8` migration, removing the `useReadCountMode` opt-in toggle, reverting Gradle/AGP downgrades, and extracting color helpers (with broken test fix) into a separate file.

**Architecture:** Append-only history table is the single source of truth. The `showMarkAsReadButton` setting is the only gate for the read tracking UX — when enabled, users see ticks plus an `x N` counter when count > 1, and can long-press the tick to open a history dialog for per-row deletion. No mode toggle. `ChapterReadingRecord` is dropped after migrating its rows 1:1 to `ChapterReadHistory`. `ReadingProgressActivity` is left as a single file (a deeper split is out of scope); only the color-math helpers move to `ReadingProgressColors.kt`.

**Tech Stack:** Kotlin/Android (Room 2.7, AGP 9.0, Gradle 9.1, Kotlin 2.2.10), Vue.js 3 + TypeScript, JUnit 4 (Kotlin tests), Vitest (Vue tests).

**Branch:** `Track-Multiple-Chapter-Reads` (already merged with `current-stable` at `6f6ff41fd`). All commits land directly on this branch — DO NOT create a new worktree (worktrees branch from `develop`, which is wrong for this work).

**Sandbox:** All `./gradlew` invocations require `dangerouslyDisableSandbox: true`. Vue.js commands run inside the sandbox.

```kotlin
private val addChapterReadHistoryTable = makeMigration(7..8) { db ->
    // Create final ChapterReadHistory schema in one shot
    db.execSQL("""
        CREATE TABLE IF NOT EXISTS ChapterReadHistory (
            id BLOB NOT NULL PRIMARY KEY,
            kjvBookOrdinal INTEGER NOT NULL,
            chapter INTEGER NOT NULL,
            cycle INTEGER NOT NULL DEFAULT 1,
            readAt INTEGER NOT NULL,
            bookInitials TEXT NOT NULL DEFAULT ''
        )
    """)
    db.execSQL("CREATE INDEX IF NOT EXISTS `index_ChapterReadHistory_kjvBookOrdinal_chapter_cycle` ON ChapterReadHistory (kjvBookOrdinal, chapter, cycle)")

    // Migrate existing ChapterReadingRecord rows 1:1 to ChapterReadHistory.
    // bookInitials is unknown for old records (the legacy table never tracked it).
    db.execSQL("""
        INSERT INTO ChapterReadHistory (id, kjvBookOrdinal, chapter, cycle, readAt, bookInitials)
        SELECT randomblob(16), kjvBookOrdinal, chapter, cycle, readAt, '' FROM ChapterReadingRecord
    """)

    // Drop the legacy table
    db.execSQL("DROP TABLE IF EXISTS ChapterReadingRecord")
}
```

```kotlin
/**
 * Color and scale helpers for reading-progress heatmaps. Pure functions — no Android lifecycle
 * dependencies — so they are unit-testable without Robolectric.
 */
object ReadingProgressColors {

    // Generic green-scale (used by both reading and memorization heatmaps)
    val COLOR_EMPTY = Color.parseColor("#E8E8E8")
    val COLOR_LOW = Color.parseColor("#C6E48B")
    val COLOR_MEDIUM = Color.parseColor("#7BC96F")
    val COLOR_HIGH = Color.parseColor("#239A3B")
    val COLOR_ALMOST = Color.parseColor("#196127")
    val COLOR_READ = Color.parseColor("#196127")

    // Memorization heatmap
    val COLOR_MEM_LOW = Color.parseColor("#C6E48B")
    val COLOR_MEM_MEDIUM = Color.parseColor("#7BC96F")
    val COLOR_MEM_HIGH = Color.parseColor("#239A3B")
    val COLOR_MEM_ALMOST = Color.parseColor("#196127")
    val COLOR_MEM_FULL = Color.parseColor("#196127")
    val COLOR_TARGET_DOT = Color.parseColor("#9C27B0")

    // Count-mode chapter heat map: amber → orange at 5 → deep red at max(max,10)
    const val HEAT_MID_COUNT = 5
    val COLOR_HEAT_MIN = Color.parseColor("#FFF9C4")
    val COLOR_HEAT_MID = Color.parseColor("#FF6D00")
    val COLOR_HEAT_MAX = Color.parseColor("#B71C1C")

    // Count-mode book heat map: light blue → dark blue at 100 % → red at scale max
    val COLOR_COUNT_BOOK_BLUE_LOW = Color.parseColor("#E3F2FD")
    val COLOR_COUNT_BOOK_BLUE_HIGH = Color.parseColor("#1565C0")
    val COLOR_COUNT_BOOK_RED = Color.parseColor("#B71C1C")

    /**
     * Round the maximum read percentage up to the next 25 % boundary so the scale lands on
     * clean labels. Below 100 % we always show 0–100.
     */
    fun resolveBookPercentScaleMax(maxReadPercent: Float?): Float {
        val actualMax = maxReadPercent ?: 0f
        if (actualMax <= 1.0f) return 1.0f
        return ceil(actualMax * 4f) / 4f
    }

    /**
     * Build the list of percent-step labels (25, 50, 75, ..., max) for the heatmap legend.
     * Always uses 25 % increments — matches resolveBookPercentScaleMax's rounding granularity.
     */
    fun buildBookPercentScaleSteps(maxReadPercent: Float): List<Int> {
        val maxPercent = (maxReadPercent * 100).roundToInt().coerceAtLeast(100)
        return (25..maxPercent step 25).toList()
    }

    // Move the bodies of countToHeatColor, countBookProgressToColor, progressToColor,
    // interpolateColor, and textColorForBackground here verbatim from ReadingProgressActivity's
    // companion object. Their signatures stay identical; only the enclosing scope changes.
}
```
